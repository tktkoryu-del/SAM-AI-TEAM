# معيار الهندسة والبرمجة

## تنظيم الشيفرة
- افصل واجهة المستخدم عن منطق المجال والوصول إلى البيانات.
- استخدم أسماء واضحة وثابتة، ووثّق القرارات المعمارية المهمة.
- تجنب الأسرار والبيانات الشخصية في المستودع والسجلات.
- ثبّت إصدارات الاعتماديات وسجّل طريقة البناء.
- اجعل التغييرات صغيرة ومحددة وقابلة للمراجعة.

## Git workflow
- فروع قصيرة العمر بأسماء واضحة: `feature/`, `fix/`, `docs/`, `chore/`.
- لا تعمل مباشرة على الفرع الرئيسي إلا لإصلاح توثيق بسيط عند الاتفاق.
- كل تغيير جوهري يمر بطلب مراجعة Pull Request.
- اكتب وصفاً يشرح السبب والنطاق والاختبارات والمخاطر.
- لا تدمج تغييرات لم تُختبر.

## مراجعة الكود
- صحة المنطق ومعالجة الأخطاء.
- سلامة المدخلات والصلاحيات.
- عدم تسريب أسرار أو بيانات.
- الأداء وإمكانية الصيانة.
- التوافق وإمكانية الوصول وRTL عند دعم العربية.
- الاختبارات والتوثيق وخطة التراجع.

## متطلبات تطبيقات الهاتف
- تحديد الحد الأدنى لإصدارات Android/iOS والأجهزة المدعومة.
- طلب أقل قدر من الأذونات وبوقت الحاجة.
- توضيح سبب كل إذن للمستخدم.
- التعامل الآمن مع البيانات المحلية والشبكة.
- اختبار حالات انقطاع الشبكة، رفض الأذونات، وتلف البيانات.
- اختبار العربية وRTL وتكبير الخط وإمكانية الوصول.

## CI المقترح
عند إضافة مشروع برمجي فعلي، أضف فحوصاً مناسبة للغته: lint، format، unit tests، build، dependency/security scan. لا تُفعّل خط أنابيب غير مناسب قبل معرفة التقنية المستخدمة.
