# Cloud Deployment Readiness

## Staging target
A Render Blueprint is included at the repository root. It is intentionally configured as:
- Frankfurt region
- Free web service
- Docker build from `services/runtime/Dockerfile`
- Automatic deploys disabled
- Random `SAM_API_TOKEN` generated by Render
- `OPENAI_API_KEY` requested as a secret at initial Blueprint creation

The container starts 12 worker processes and then the coordinator. Workers bind only to loopback inside the container; the coordinator binds to the platform's public service port and requires a bearer token for non-health API routes.

## Important limitations
This is a staging template, not a production deployment:
- Render free web services sleep after 15 minutes idle and may restart.
- The task store is local JSON files and is not durable across instance replacement.
- The free service does not provide an always-on background worker or persistent disk.
- OpenAI API usage is billed separately. Do not supply a billable API key or run paid inference without budget approval.
- No Render account was connected and no cloud resource was created by this change.

## Production blockers
Before production, replace JSON task files with a durable queue/database, implement restart recovery, add rate limiting and audit logging, configure a secret manager and alerting, and select a paid always-on compute/database plan with an approved spending ceiling.
