# دورة التنفيذ الموحدة

## المراحل
1. **Intake:** وصف المشكلة والنتيجة المطلوبة والمستخدم المستهدف.
2. **Discovery:** جمع المعلومات وفحص الموجود وتحديد المجهول.
3. **Requirements:** متطلبات وظيفية وغير وظيفية ومعايير قبول.
4. **Planning:** تقسيم العمل، تقدير الجهد، التبعيات والمخاطر.
5. **Design:** معمارية أو تدفق UX أو تصور إنتاج.
6. **Implementation:** تنفيذ أصغر دفعة قابلة للفحص.
7. **Verification:** اختبارات ومراجعة أمنية وجودة.
8. **Release readiness:** فحص الإصدار والنسخ الاحتياطي وخطة التراجع.
9. **Approval:** موافقة المستخدم قبل النشر أو الدفع أو الإجراء الخارجي.
10. **Delivery:** تسليم الملفات والروابط وسجل الاختبارات والقيود.
11. **Operations:** متابعة الأعطال والمؤشرات والتحسين.

## بوابات الانتقال
- لا يبدأ التنفيذ دون نطاق ومدخلات كافية.
- لا تُدمج تغييرات تقنية دون مراجعة.
- لا يمر إصدار مع فشل حرج أو ثغرة عالية غير معالجة.
- لا يُنشر أي محتوى أو تطبيق دون موافقة صريحة.
- لا تُغلق المهمة دون دليل تحقق.
