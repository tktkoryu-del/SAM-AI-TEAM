# بروتوكول البحث عن الترند والتقنيات الحديثة

## متى نبحث؟
يُنفذ بحث حديث قبل أي مهمة تتعلق بصناعة المحتوى، التسويق، المنصات، المنتجات، التطبيقات، الذكاء الاصطناعي، الأسعار، القوانين، مواصفات النشر أو أدوات الإنتاج. في المهام الثابتة أو التحريرية البحتة لا نضيف بحثاً بلا فائدة.

## تسلسل البحث
1. صياغة سؤال بحث محدد: ما الذي تغير؟ ما الأكثر استخداماً/طلباً؟ وما الذي يناسب جمهور SAM؟
2. أولوية المصادر:
   - المصدر الرسمي للمنصة أو التقنية أو المنتج.
   - توثيق المطور وإصدارات البرامج وسجلات التغيير.
   - بيانات واتجاهات حديثة موثوقة.
   - تجارب ومناقشات المستخدمين كمصدر نوعي مساعد، لا كحقيقة نهائية.
3. تحقق زمني: تاريخ النشر/التحديث، البلد، اللغة، والمنصة.
4. تحقق متقاطع من مصدرين مستقلين عندما تكون المعلومة مؤثرة.
5. ترجمة النتائج إلى قرار تنفيذي، لا مجرد تجميع روابط.

## بطاقة الاتجاه
لكل اتجاه مرشح سجّل:
- الاسم والوصف.
- تاريخ/نافذة الرصد.
- المنصة والجمهور والمنطقة.
- الدليل والرابط.
- حجم الإشارة: قوي / متوسط / ضعيف، مع سبب.
- ملاءمة هوية SAM والجمهور.
- تكلفة الإنتاج والوقت والمخاطر وحقوق الاستخدام.
- قرار: نفّذ / اختبر صغيراً / ارفض.

## اختيار الفكرة
قيّم داخلياً كل فكرة وفق:
- صلة الجمهور والهدف.
- حداثة الإشارة وقوة الدليل.
- إمكانية التميز لا التقليد.
- سهولة الإنتاج وجودته.
- مخاطر حقوق النشر والسلامة والسياسات.
- قابلية القياس والتحسين.

لا تختلق أرقام مشاهدات أو نمو أو نسب نجاح. لا تعتبر نتيجة بحث واحدة إثباتاً للترند. لا تستخدم موسيقى أو صوراً أو مقاطع محمية دون ترخيص مناسب.

## تحديث التطبيقات والتقنية
- راجع وثائق الإصدارات الرسمية وسياسات المتاجر قبل تثبيت SDK أو مكتبة أو API.
- تحقق من توافق الإصدارات وتاريخ الدعم وملاحظات الأمان.
- ثبّت إصدارات الاعتماديات وسجّل سبب الاختيار.
- لا تُدخل مكتبة جديدة لمجرد أنها رائجة؛ يجب أن تحل حاجة حقيقية.
