# بوابة الجودة والقبول

## مستويات الخطورة
- **Critical:** فقد بيانات، كشف أسرار، تجاوز صلاحيات، أو تعطل أساسي. يمنع التسليم.
- **High:** خلل رئيسي أو خطر أمني كبير. يمنع الإصدار حتى الإصلاح أو قبول استثناء موثق من صاحب الصلاحية.
- **Medium:** خلل محدود مع بديل واضح. يوثق ويحدد له موعد.
- **Low:** تحسين غير مانع. يسجل في قائمة التحسينات.

## قائمة قبول عامة
- [ ] المتطلبات ومعايير القبول محددة.
- [ ] السيناريوهات الأساسية تعمل.
- [ ] حالات الخطأ والحدود مختبرة.
- [ ] لا توجد أخطاء Critical أو High مفتوحة.
- [ ] الخصوصية والأذونات متوافقة مع الغرض.
- [ ] لا توجد أسرار في الملفات أو السجلات.
- [ ] الأداء والاستقرار مقبولان على الأجهزة المستهدفة.
- [ ] العربية وRTL مختبران عند انطباقهما.
- [ ] التوثيق وتعليمات التشغيل مكتملة.
- [ ] يوجد دليل اختبار قابل لإعادة التنفيذ.
- [ ] خطة تراجع أو استعادة متاحة.
- [ ] موافقة المستخدم على النشر/الإصدار مسجلة.

## أنواع الاختبارات
1. Static analysis وlint.
2. Unit tests.
3. Integration tests.
4. UI / end-to-end tests.
5. Security and privacy review.
6. Performance and reliability.
7. Accessibility and localization.
8. Release smoke test.

## سجل العيوب
لكل عيب: المعرف، الوصف، خطوات إعادة الإنتاج، المتوقع، الفعلي، الشدة، البيئة، الدليل، المسؤول، الحالة.

## قرار QA
- PASS: كل الشروط الإلزامية مستوفاة.
- CONDITIONAL PASS: لا توجد عيوب مانعة مع استثناءات موثقة وموافقة صاحب الصلاحية.
- FAIL: يوجد شرط إلزامي غير مستوفى.
